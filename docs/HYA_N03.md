# HYA-N03 · 渠道需求、履约口碑与并行清洁

依赖N05（PR #19）。审计发现营销满级的旧到店间隔仍为2.727秒，12房需求覆盖约40%，而单工位清洁又限制持续吞吐。单纯按房数放大客流会掩盖两个独立瓶颈。本次房数不参与渠道速率计算；新增core/demand统一配置与只读诊断，保留100ms状态机和唯一退房入账入口。

| 驱动     | 规则                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- |
| 路过咨询 | 每6秒1次                                                                                                    |
| 预订渠道 | 每级营销每秒0.085次                                                                                         |
| 企业渠道 | 每级品牌每秒0.065次；已建酒廊额外0.025次                                                                    |
| 回头咨询 | 每秒0.16×已获得口碑；初始为0                                                                                |
| 咨询转化 | 基础0.82，偏好设施覆盖最多+0.12，实际履约声誉最多+0.1；价格超过品质参考价1.2倍后每超一倍-0.14；限制0.4–0.97 |
| 口碑     | 只在真实退房时增长，房间服务基础质量0.65，偏好设施全部完成可达1；每单增长0.01×(质量-0.4)，上限1             |
| 清洁     | 原周期加速保留；清洁2/4级分别增加班组，最多3间同时清洁                                                      |

咨询不等于到店，更不会产生收益。未转化、满队离开、排队超时分开记录；offered=converted+rejected，lost维持原到店流失含义。旧v1档可缺少demand，首次tick补初值，不追溯口碑、不改锁定订单、不发离线收入。新统计严格校验，保留坏档导出流程。手动/自动清洁共用同一容量限制，按钮可在尚有空闲班组时继续安排，进度显示最快完成任务与同时工作组数。

概览提供渠道/分钟、咨询转化、离队原因、平滑近期入住率、班组数和瓶颈建议。推荐优先解决脏房积压/低需求，仍使用N01固定尺寸槽位；无收益或提示参与主布局。定价描述明确价格/品质转化关系，预览使用咨询间隔，避免宣称每次咨询都会到店。

验证：32/32单测、typecheck/lint/build通过。新增三种种子12房1800秒回放，600秒预热后入住率均超过65%，验证咨询守恒/不重复结算；另测扩房不生客流、设施/价格对转化的影响、口碑只从履约累积、旧档无口碑、损坏统计拒绝、三组清洁互斥。原3条购买策略仍在1800秒内到达终局。7个原交互/经济/布局E2E通过；新增供需E2E验证真实350元营销购买使预订从0变为5.1次/分钟，暂停/恢复与概览显示。

回放：同seed1731、1/4/8/12房各3600游戏秒，前120秒预热，100ms采样；原始数据见evidence/n03。全升级不含新设施的12房平均入住率由main基线39.8%变为81.2%；8房由59.7%变为82.3%。这是累计N04客群+N03渠道/班组效果，N05同客群基线为8房68.3%、12房45.5%，用于隔离本PR影响。无升级的12房仍受单清洁班组限制，不能仅靠扩建获得高入住率。渠道满级的小酒店会积压与流失，界面应据此提示扩容而非保证满房。

复现：先用rolldown将scripts/economy-audit.mjs按node平台打包为临时mjs，再用Node运行；HEYAT_AUDIT_OUTPUT指定JSON路径，HEYAT_AUDIT_LABEL指定源版本标签。新增代码未改变模型/材质/灯光预算。预览npm ci && npm run dev；运行tests/e2e/demand.spec.ts可重现4房诊断与购买场景。证据为真实Three.js截图。

已知边界：渠道是游戏中的连续到店咨询率，非真实酒店预测；口碑与需求参数仍需玩家长期体验调优。人物动画独立由N06处理。软件渲染采样不代表真实手机，MOBILE_PERF_UNVERIFIED。本PR不自动合并。
