# HYA-N05 · 四种可经营设施

原工程只有客房房费，设施偏好尚无履约、容量或消费。本次通过既有BUY命令与退房结算入口增加四设施，不新建平行经营系统。依赖N04（PR #18）；仍使用version1，新增订单服务/设施统计均为可选字段。旧订单不追溯收费，存档中途恢复保留锁定服务报价、剩余时间和服务状态。

| 设施     | 初建价格 | 解锁            | 初级服务费/时长 | 三级容量 |
| -------- | -------: | --------------- | --------------- | -------: |
| 早餐厅   |      900 | 4房             | 18 / 3秒        |        3 |
| 健身房   |     1800 | 4房             | 12 / 4秒        |        3 |
| 行政酒廊 |     6000 | 2层、品牌1      | 45 / 3秒        |        3 |
| 天台酒吧 |    14000 | 3层、8房、品牌2 | 30 / 4秒        |        3 |

每种三级，升级成本×2.2、每级新增服务位、收费+30%基价、服务时间除以1+0.2×增级数。入住时按客群偏好和已建设施生成服务单；按订单顺序占用有限服务位。服务完成仅记录履约，退房统一将已完成服务费与锁定房费入账一次，未服务不收费并记录错失。界面显示服务位、排队、履约与真实累计设施收入。所有规则集中在core/facilities.ts。

场景增加前庭早餐台、左侧健身亭、右侧行政休息亭和屋顶后侧酒吧，复用建筑批处理几何/材质，不增加实时灯或动态阴影。亭顶使用开放框架，保留客房剖面视线；四设施标签为场景注释，远景阅读仍以运营面板为准。

验证：28/28单测、typecheck/lint/build通过；设施+原游戏+画质回归7/7通过，最后视觉调整后设施E2E再次1/1通过。覆盖解锁、购买、容量/排队、报价锁定、只收已履约费用、重复推进不重复结算、服务中存档恢复、拒绝损坏费用；E2E真实购买四设施、导出场景报告、重载保留等级，并验证126房费+18早餐=144只入账一次。
