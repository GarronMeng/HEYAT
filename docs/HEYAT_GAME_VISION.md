# HEYAT HOTEL｜游戏整体定调与设计规格

> 版本：V0.9（可用于原型开发，待实机验证）  
> 日期：2026-10-22  
> 项目仓库：`GarronMeng/HEYAT`（私有、`main`；文档导入时仓库已由 README 引导初始化，尚无游戏源码）  
> 类型：短流程主动型增量游戏（Active Incremental）× 轻策略酒店经营 × 3D 微缩场景  
> 本文为正式开发的产品基线，数值、性能与商业名称仍以测试及核验结果为准。

## 1. 一句话定位

**从亲手接待第一位客人，到让一座精致而荒诞的 HEYAT 酒店自动运转。**

- 游戏名（工作名）：**HEYAT HOTEL**；中文副标题（工作名）：**今晚有套吗？**
- 核心情绪：高级酒店氛围 + 持续增长的爽感 + 对酒店行业的轻微戏谑。
- 核心卖点：**看得见的增长**——每次升级都尽量改变客房、客人、灯光、客流、动画、楼层或收入反馈。
- 平台路线：Web Demo（桌面 Chrome、iPhone Safari）→ 用户测试 → 评估 Steam 付费发行。
- MVP：20–30 分钟；完整付费版目标：3–5 小时，有明确终局、通关后可选择重玩。
- 玩家画像：喜欢《Digseum》《Nodebuster》《Bills Must Be Paid》式短流程数值成长，同时喜欢精致酒店 / 经营空间的玩家。此为定位假设，须通过测试验证。

## 2. 产品设计支柱（不得为了美术牺牲）

1. **30 秒有反馈**：第一次操作立即看到现金、角色、房间状态变化。
2. **5 分钟有跃迁**：第一次关键自动化升级明显减少玩家重复操作。
3. **15 分钟有形态变化**：酒店实实在在扩建，而不只是 UI 数字增加。
4. **升级引发新瓶颈**：增大客流可能压垮前台；前台优化后清洁/房量成为瓶颈；房型升级提高单客价值。
5. **确定性成长、有限终局**：总体趋势持续改善，避免玩家因失败惩罚而重复劳动；以效率决策拉开进度差异。
6. **清楚 > 复杂**：同一时刻最多一个主面板，玩家始终看到当前收益、可购买升级、下一目标。

## 3. 必须保持的美术基调

### 3.1 基准：已选择的「图三」

**Premium Stylized Realism / Isometric Cutaway Diorama**：深蓝城市夜景、暖金客房灯光、精致酒店大堂、玻璃与黄铜点缀、现代高级材质；有真实建筑比例，但不是写实建筑模拟器。

- 相机：固定 3/4 俯视或近正面剖面的正交/弱透视摄影机；可缩放与轻微水平旋转（具体旋转范围经模型遮挡测试确定），禁止无限自由视角。
- 核心场景：一栋可逐层向上扩建的酒店；低层大堂与前台，楼上模块化房间；可观察真实房态。
- 角色：正常人体比例但细节简化；不使用 Q 版大头，不追求照片级面孔。近景骨骼角色少量，中景动画简化，远景用 Sprite / 贴图人物。
- 重点光影：大堂、走廊、客房的暖光，外部深蓝夜色；通过烘焙、发光贴图、局部轻量动态光营造氛围。
- 风格性幽默：主要放在升级名称、品牌标语、事件文本和结算页面，不让画面变成纯搞笑卡通。

### 3.2 初步视觉规范（允许美术试验后微调）

| 用途 | 初始色值 | 说明 |
|---|---|---|
| 深夜蓝 | `#0C1C2B` | 背景、主界面 |
| 深海军蓝 | `#122B3E` | 浮层、系统面板 |
| 黄铜金 | `#C6A46B` | 酒店品牌与高级感 |
| 暖象牙色 | `#F2E6D2` | 标题、文案 |
| 青绿色 | `#47A48D` | 收益、可完成升级 |
| 琥珀色 | `#F0B95F` | 重要升级与里程碑 |
| 暖红色 | `#DB786A` | 等待、房态提示，非失败惩罚 |

中文界面正文用高可读系统字体 / 授权商用字体；数字使用等宽数字；标题字体授权确认后再定。避免细小的全大写英文、金色小字堆满界面。

### 3.3 画面变化应由游戏状态驱动

| 游戏事件 | 必须看到的视觉变化 |
|---|---|
| 客人抵达 | 大堂出现行李客人、队列变化 |
| 办理入住 | 人物移向房间，房态转为入住，暖灯点亮 |
| 退房 | 客人离开，房态改为待清洁 |
| 清洁完成 | 清洁车 / 短动画、房间恢复整洁 |
| 升级房型 | 房间模型与装饰层级变更，不只提升数字 |
| 自动化解锁 | 前台/清洁动作由系统自动执行，展示连续运转 |
| 新楼层 | 建筑向上生长，附带短暂施工动画和明显音效 |
| 收益爆发 | 适量金币/金额粒子；不得遮挡主要场景与 UI |

**注意：游戏逻辑中的客人人数与渲染角色数分离。** 酒店可拥有数十名真实模拟客人，但画面仅挑选代表性角色展示；其余通过灯光、房态、队列规模与统计体现。

## 4. 玩家行为和经营逻辑

### 4.1 三重循环

1. **订单循环（约 10–30 秒）**：客人抵达 → 排队 / 自动分配 → 入住 → 退房 → 待清洁 → 再次可售。
2. **升级循环（约 1–5 分钟）**：获得现金 → 识别瓶颈 → 选择收益 / 效率 / 规模升级 → 立刻看到变化。
3. **扩建循环（约 15–60 分钟）**：解锁新房型 / 楼层 / 酒店等级 → 新瓶颈 → 更强升级 → 旗舰酒店里程碑。

### 4.2 玩家主动做什么

玩家不能只看进度条等待。初始手动办理入住/安排清洁；中后期主动选择升级路线、设置房价策略、对关键拥堵环节进行短时加速（可选“经理亲自上阵”主动技能，冷却与价值须平衡）。**主动操作提供更高效率，但不变成必须不断点击的惩罚。**

### 4.3 资源、指标与边界

- **现金 Cash**：主要可消耗资源，用于升级、建房、扩建；所有消费必须可解释。
- **声望 Prestige**：主要由里程碑和品牌升级产生，作为等级解锁门槛；MVP 不做无限挂机积攒声望。
- **经营指标（非货币）**：客流需求、前台处理能力、清洁能力、可售房间数、订单收入、入住率、酒店评级。
- **暂不做**：负债、股价、税收、复杂工资报表、餐饮经营、全球多酒店、多币种经济、广告、付费道具、多人在线。
- **MVP 无转生重置**；正式版可在玩家通关后研究“品牌重塑 / 开设第二家店”的 New Game+，不能用频繁重置拉长内容。

### 4.4 核心房态机（唯一事实来源）

`LOCKED → AVAILABLE → RESERVED → OCCUPIED → DIRTY → CLEANING → AVAILABLE`

- `RESERVED` 是已分房但未入住；离店先转换 `DIRTY`，不能直接 `AVAILABLE`。
- 前台、房态、清洁与客流采用同一模拟器事件模型；不得在动画代码中独立修改余额或房态。
- 所有客房状态有可追踪时间戳；刷新和恢复后不能重复结算。
- 需求增量会形成队列 / 等待，但不应导致无限增长的内存队列；超过上限可记录流失客流的统计值。

### 4.5 经济模型（待自动化模拟标定）

定义：

- `arrivalRate`：每分钟到店客人数；
- `deskRate`：每分钟前台可办理入住量；
- `cleanRate`：每分钟完成清洁的房量；
- `roomCycleLimit`：取决于可售房间数量及平均入住+清洁周期；
- `actualCheckIns = min(arrivalRate, deskRate, cleanRate, roomCycleLimit)`（用于长期稳态吞吐量近似，实际运行使用房态与离散事件，不将此近似直接写成结算逻辑）；
- `cashPerMinute ≈ actualCheckIns × avgRevenuePerStay`。

升级应改变至少一个可观察的机制值，而不只是无意义的百分比叠加。经济模拟工具必须支持批量试算、随机种子、进度曲线输出、可达性 / 死锁检查。

### 4.6 MVP 升级树：12 个代表项

| 分支 | 升级 | 改变什么 | 可视反馈 |
|---|---|---|---|
| 收益 | 客房定价 | 订单收益 | 收费数字变化 |
| 收益 | 更好的床 | 客房等级 / 单价 | 床具外观升级 |
| 收益 | 豪华房改造 | 高价值房型 | 房间装修变化 |
| 收益 | VIP 礼遇 | VIP 订单价值 | 特殊客人出现 |
| 效率 | 快速办理入住 | 前台吞吐 | 排队加快 |
| 效率 | 自动入住机 | 手动→自动 | 自助机出现 |
| 效率 | 加速清洁 | 清洁周期 | 清洁动画变快 |
| 效率 | 自动清洁 | 手动→自动 | 清洁车自动运行 |
| 规模 | 宣传投放 | 到店客流 | 大堂更繁忙 |
| 规模 | 增加客房 | 可售容量 | 新房亮灯 |
| 规模 | 扩建楼层 | 楼层与房量 | 酒店明显长高 |
| 规模 | 品牌等级 | 新内容解锁 | 招牌/大堂变化 |

升级采用数据驱动配置；价格、等级上限、前置条件、收益倍率都不得在 UI 中硬编码。升级需要表达前后变化、收益回本时间或推荐原因。

## 5. 首 30 分钟体验节拍（目标，不是已验证结果）

| 进度 | 体验事件 |
|---|---|
| 0–1 分钟 | 1 间客房营业，首位客人入住，完成第一笔结算 |
| 1–3 分钟 | 看到前台和清洁瓶颈，升级房价 / 加速流程 |
| 3–5 分钟 | 自动入住解锁，操作方式真正改变 |
| 5–10 分钟 | 自动清洁与增加客房，场景活跃度显著提升 |
| 10–15 分钟 | 解锁高价值房型，形成需求与收益选择 |
| 15–20 分钟 | 完成明显的酒店扩建 / 评级提升 |
| 20–30 分钟 | 第二层成熟运转，达成 Vertical Slice 终点，给出正式版扩展预告 |

通关 MVP 不要求玩家无休止等待某笔巨款；如果出现 >90 秒没有有意义决定或反馈的空窗，则为待修复设计问题。

## 6. UI / UX 结构

### 6.1 桌面布局

- 顶部常驻：Cash、每分钟收入、Prestige、入住率/客房状态、酒店等级；不超过 5 个常驻主指标。
- 中央：建筑剖面 3D 场景，占据画面视觉主体。
- 左侧：当前目标/里程碑，不同时展示大量任务。
- 右侧：可折叠的升级抽屉，以收益、效率、规模分组；一次只有一个主抽屉。
- 底部：主要操作（酒店、升级、扩建、概览）与**下一项推荐升级**。

### 6.2 iPhone 浏览器

- 横屏为主要美术体验，但不能完全屏蔽竖屏。竖屏用单列 HUD + 全屏场景 + 底部抽屉，保持核心循环可玩。
- 安全区适配 `env(safe-area-inset-*)`；触摸目标建议 ≥44 CSS px；不能依赖悬停。
- 重要数值不得只靠颜色区分；按钮有购买不可达状态说明。
- 3D 场景支持拖动（有限平移）、双指缩放、点击房间；通过射线拾取房间代理碰撞体，减少点击误判。
- 弱网加载展示进度和重试，WebGL 初始化失败必须提供可理解的错误与低配模式，不显示空白页。

## 7. 品牌与原创性边界

- **HEYAT 是暂定工作名，不等于完成商标清查。** 它与现有知名酒店品牌 HYATT 存在音形近似性；商业发行前需要针对游戏软件/娱乐服务等类别和目标销售地域开展商标与混淆风险核验。
- 原创字标、原创徽记、原创酒店建筑与制服，禁止直接临摹凯悦及其他现实酒店的徽记、商标字体、平面设计、特定招牌、受版权保护的照片。
- 先前制作的现实酒店参考模型必须经过资产来源和使用权审计，不能直接放进商业版。
- 轻度调侃以酒店行业一般现象为对象，避免虚构对特定现实品牌的不实负面表述。

## 8. 本阶段已经锁定与待验证

**暂按已锁定执行：** 图三精致夜景基调；半写实建筑+轻量角色；单栋酒店；固定剖面等距相机；主动型增量+自动化；网页优先；初期不做广告与充值；有限游戏终局。

**必须在开发中验证：** 具体升级价格、成长倍率、30 分钟可玩性、玩家愿付费程度、目标 iPhone 最差帧率、人物数量上限、竖屏细节、美术生产效率。

**上线前必须确认：** 产品最终商用名称及商标、场景/贴图/字体/音频资产授权、Steam/平台政策和定价。

## 9. 不可牺牲的交付定义

首个可验收版本应让玩家在真实 iPhone 和桌面浏览器中，于约 30 分钟内从一间小旅馆成长为自动化酒店：客人真实到店、入住/清洁/离店可视、升级引发明确经济和视觉变化、扩建改变 3D 建筑、保存与读档正确、发生性能压力可自动降级。概念图只是美术方向，不是保证每个模型都具备同样的复杂度。
